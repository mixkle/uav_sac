# Baseline best：按联网跳数缩放运动速度

本轮是冻结策略的执行干预，不训练新模型，不修改baseline训练配置或默认环境。

模型固定为3邻居、容量10、覆盖＋数据率baseline 1M best（实际671,744步）。使用32个验证场景10000–10031、动作采样种子880001、16环境批次、CPU8线程／Numba4线程，各执行400步；不使用保留测试集。

两组：原速度、用户提出的跳数缩放。动作执行前取 `h = min_g B[u,g]`，联网时：

`alpha(h) = 0.25 + 0.75 * (1 - exp(-0.4*(h-1))) / (1 - exp(-0.4*18))`

代码合法联网跳数为1–18，不可达标记为19。断联按不可达判断，alpha=1；用户原文“断联跳数18”未被用于误判合法18跳路径。速度公式的分母保持18，未改为17。

直接接入BS的alpha=0.25；2跳约0.4974，3跳约0.6633，4跳约0.7745。只缩放物理指令位移，圆盘动作和历史中的上一动作保留actor输出；UE运动、每步1秒、400步终止、无线、关联和奖励全部保持。边界反射在缩放后执行，反射指标与未缩放指令区别处理。

实现只位于诊断模块 `src/uav_research/hop_speed_diagnostic.py`，不接入生产工厂。当前环境没有新增训练开关，原baseline启动行为不变。

## 结果

[完整报告与图表](../analysis/baseline3_best_hop_speed_025_k04/report.md)

| 指标 | 原速度 | 跳数缩放 |
|---|---:|---:|
| 全回合覆盖 | 58.631% | 57.730% |
| 前100步覆盖 | 50.057% | 44.068% |
| 后100步覆盖 | 61.021% | 64.007% |
| 终态覆盖 | 61.500% | 64.583% |
| 总吞吐Mbps | 481.47 | 472.20 |
| 平均断联 | 11.741% | 9.561% |
| 每回合最大单步覆盖跌幅均值 | 46.875pp | 35.063pp |
| 实际速度m/s | 15.86 | 8.42 |

平均断联差约−2.18pp，配对场景95%区间[−3.61,−0.82]pp；最大单步跌幅差−11.81pp，区间[−17.81,−5.98]pp。全程覆盖、后100步覆盖和吞吐差的区间均跨零，不能宣称整体任务表现提高；两组32/32场景仍都出现≥10pp单步骤降。靠边150m内比例从5.05%升至8.38%，反射比例则从0.42%降至0.31%，两者需要区分。

本轮原速度CPU控制组复现历史CPU口径58.63125%，不要与此前CUDA口径56.43844%混用。同一整数种子在CPU／CUDA上不产生同一高斯噪声流。

初始布局、UE完整路径、动作采样前随机状态序列及首步原始动作均通过跨组哈希核对。actor冻结、critic不参与决策或审计；源检查点哈希未改变。针对公式、时序、历史、恢复、参考路径一致性及反射的4项测试通过。
