# 后期服务能力与部署稳定性：统一复评口径

结果入口：[所有已保留实验复评](../analysis/tail100_all_completed_results_20261110/report.md)。主表固定五项指标，不修改原奖励、原训练预算或历史best的选模方式。

## 五项指标

每个完整回合400步，仅统计动作执行后的状态，初始t0不进入计算。每场景UAV服务覆盖为唯一实际关联的UE人数/场景UE总数。感知率不代替联网服务覆盖率。

1. `tail100_coverage_pct`：第301–400步覆盖率的时间平均，再对场景平均，单位%。
2. `final_coverage_pct`：第400步覆盖率的场景平均，单位%。
3. `tail100_throughput_mbps`：第301–400步系统总吞吐的时间平均，再对场景平均，单位Mbps。
4. `final_throughput_mbps`：第400步系统总吞吐的场景平均，单位Mbps。
5. `tail100_coverage_std_pp`：先求每条轨迹后100步的总体时间方差（ddof=0），对场景和动作重复平均方差后开根号。单位百分点pp。这是合并场景内方差的RMS时间标准差，延续上一次5.995/4.594pp的口径。

另外保存`tail100_scene_std_pp`，它是各条轨迹标准差的算术平均，不作为主表σ。两者因开根号和平均次序不同而不相等。不能把32个场景×100步全部混合后求标准差，也不能在重复动作种子的曲线先平均后求标准差。

旧`reward_curves.npz`没有吞吐序列时，用其中未加权的原始tau乘来源配置的`num_users*rate_reference_bps`恢复总吞吐；不通过总奖励反推。独立感知、断联、鲁棒性权重不影响这个换算。主表不按UE人数再次平均吞吐。

## 范围与可比性

- 覆盖清理后保留的20个正式运行best/last，以及两组跳数缩放10M、初始化、教师、执行约束、泛化和定位诊断。
- 独立actor的1M历史模型和1.2M模型分别使用对应快照，不让当前1.2M权重覆盖1M记录。
- 旧结果优先读取真实保存轨迹。统计口径统一，不把CPU/CUDA或动作种子导致的不同轨迹冒充同一数据；每条记录保留设备、场景、动作重复、模型实际步数。
- 场景660000起的64场景泛化与10000起的32场景验证分开展示；UE/UAV数量和容量不同也分开。
- 冻结轨迹上的Top-K影子关联另表，不称为闭环策略。最大匹配O1/O2只提供覆盖人数上界，不虚构最优吞吐。
- 只存代表拓扑、均值曲线、短分叉或已删除检查点的数据不能恢复完整统计；历史删除清单单独记录，不编造结果。
- best沿用当时选模定义；复评不按新指标重选best。未来改变选模标准需要另立实验协议。

六份缺少逐步数组的冻结模型已补齐CUDA验证：邻居6/7/8的last、原baseline10M的last、SAC best/last。与原日志的全回合覆盖/吞吐核对到浮点舍入误差。为恢复历史纯覆盖CPU对照，同时补SAC best/last各三套动作种子（880001/880002/880003）。全部冻结执行，不更新actor/critic、优化器或归一化统计，不使用保留测试集。

## 不确定性和数据保护

2000次bootstrap，种子950001，单位为场景；每个场景内先平均动作重复的轨迹统计量。σ在每次bootstrap内对平均方差重新开根号。区间不是训练种子不确定性。

所有原始数组及来源配置记录SHA256，计算前后核验；新文件位于独立目录，不修改旧报告和模型。完整表为summary.csv，逐场景为per_scene.csv，源数据路径/哈希和别名映射同时保存。

低σ必须和高覆盖一起解释。后100步也不自动意味着达到最大覆盖或稳态；本次使用所有方法一致的固定窗口，不挑选各自表现最好的时段。
