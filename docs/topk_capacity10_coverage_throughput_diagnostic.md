# 容量10、覆盖＋数据率基准：固定布局关联诊断

本次以用户指定的新工作基准为来源，不再复用容量20教师的布局，也不临时修改容量。

- 基准配置：`configs/mappo_coverage_throughput_capacity10_1m.yaml`。
- 源运行：`runs/mappo_coverage_throughput_capacity10_1m_seed0/`，完成1,000,000条联合转移。
- 冻结检查点：该运行的 `best.pt`，实际来自671,744步；按32场景完整回合任务回报选模。
- 训练与影子任务奖励均为 `coverage + 0.1 * tau`，其中 `tau=总吞吐/(150×5 Mbps)`。鲁棒性和断联仅作诊断。
- 真实策略仍为共享连续高斯MAPPO＋一步历史＋时间因子critic；不是扩散actor，也没有受训练的服务评分头。
- 容量10及其2 MHz单链路带宽保持原样；本次链路速率缩放因子为1。

验证场景10000–10031、每场景400步，共12,800条真实联合转移；动作采样种子880001、批次16、CPU8线程、Numba4线程。先复现源模型平均覆盖58.63125%和回合回报260.2033635897416，不符合记录则停止审计。保留测试场景不参与。

## 评分与影子关联

每个真实转移只执行一次动作及UE运动，保存动作前/后的候选图、无线量、拓扑、实际关联和历史。每种影子方案使用同一组物理数组，结果不写回下一观测或真实关联。

候选要求当前发现、下行SINR达标且本机可达任一BS。评分只使用动作前信息：

| 评分 | 定义 |
|---|---|
| SINR教师 | `sigmoid((SINR_t - threshold)/10)`；没有跳数或已有服务偏好 |
| 常数 | 全部0.5；确定性编号平局规则 |
| 随机 | 每候选边独立均匀评分，每转移20次；独立PCG64，种子由970001、场景、时刻、重复编号组成 |

| 关联方案 | 定义 |
|---|---|
| P0 | 动作前每机按评分提议Top-10，运动后过滤失效边，UE选最高分UAV；不补位 |
| P1 | 保留P0所有有效连接，空闲UAV按原评分申请未尝试候选；已服务UE拒绝，未服务UE接纳；重复直至无申请 |
| O1 | 动作前后均合法的已评分边上，精确容量约束最大匹配 |
| O2 | 全部动作后合法边上，精确容量约束最大匹配 |

P1不读取免费的全局未服务名单，记录申请、拒绝与补位轮数。O1/O2只最大化人数，不宣称其任意匹配的吞吐或两项任务奖励最优。

逐转移检查 `S_P0 <= S_P1 <= S_O1 <= S_O2 <= 150`，并分解：

```
协议损失 = S_O1 - S_P0
简单补位收益 = S_P1 - S_P0
剩余重分配缺口 = S_O1 - S_P1
时序机会缺口 = S_O2 - S_O1
当前物理图与容量残余缺口 = 150 - S_O2
```

其中 `150-S_P0 = 协议损失 + 时序机会缺口 + 残余缺口`。同一方案四项加权贡献之和等于任务奖励，后两项贡献严格为零。没有训练或修改生产关联规则。

## 执行与保存

```bash
OPENBLAS_NUM_THREADS=1 MKL_NUM_THREADS=8 OMP_NUM_THREADS=8 \
.venv/bin/python -u scripts/diagnose_topk_capacity.py \
```

## 与旧诊断的区别及结论边界

旧 `analysis/topk_capacity10_shared_best_diagnostic/` 是容量20、纯覆盖教师布局的容量10反事实；本次源模型已在容量10、两项奖励下训练，访问的布局不同，奖励口径也不同。因此不能把两个报告之间的差值归因于“重新训练容量10”这一单一因素，不能将它们当作同轨迹配对实验。旧数据全部保留。

判断评分作用时同时看覆盖、吞吐、任务奖励的绝对变化，不能只看归属变化率。补位收益应同时报告绝对人数和覆盖百分点；高空闲率本身不是浪费证据，因为总容量180仍大于150名UE。

本轮不检验受训练评分网络的效果，不将影子收益当成闭环收益。即使评分或补位改变当前收益，实际加入环境后也可能通过后续服务标记、历史和动作改变访问布局，需要独立闭环实验。

## 本轮结果（2026-11-03）

已完成完整审计，源模型覆盖58.63125%、回报260.2033635897416精确复现。未更新任何网络或生产关联。总耗时145.01秒，采集86.67秒、审计45.79秒、报告11.92秒，峰值RSS1.338 GiB，结果约841.9 MiB。16项相关测试通过。

| 评分 | P0一轮Top-K覆盖 | P1补位覆盖 | O1同信息最大覆盖 | O2动作后最大覆盖 | P0吞吐Mbps | P1吞吐Mbps |
|---|---:|---:|---:|---:|---:|---:|
| SINR教师 | 55.18438% | 55.24443% | 55.31974% | 58.63292% | 480.976 | 481.098 |
| 常数 | 54.79083% | 55.18849% | 55.31974% | 58.63292% | 455.038 | 458.333 |
| 随机，20次均值 | 54.79452% | 55.17629% | 55.31974% | 58.63292% | 455.273 | 458.444 |

**评分有实际作用，其中吞吐变化比覆盖变化更明显。** SINR教师相对随机评分的P0覆盖高0.38985个百分点，95%场景区间[0.35025,0.42993]个百分点；吞吐高25.703 Mbps，区间[22.972,28.613] Mbps，约为随机评分吞吐的5.65%。每步任务奖励高0.00732564，其中约0.00389852来自覆盖、0.00342713来自数据率贡献。随机评分会在93.81%的转移中改变至少一个UE归属、43.93%的转移中改变服务人数；高变化频率不能替代上述收益的绝对量级。

**补位确实恢复覆盖，但SINR教师下的绝对增益很小。** 教师P0的协议损失为0.20305人/步，即0.13536个百分点；补位恢复0.09008人/步，即0.06005个百分点，区间[0.04989,0.07084]个百分点，回收约44.36%的协议缺口。随机评分补位恢复0.57265人/步，即0.38177个百分点，区间[0.34875,0.41318]个百分点，回收约72.69%。因此补位对较差评分有更明显的兜底作用，但不能预期其单独解决整体覆盖问题。

**先评分后移动的时序限制更大。** O2比O1高3.31318个百分点，对应4.96977人/步，明显大于教师评分的0.13536个百分点协议损失。源baseline使用动作后集中关联，其58.63125%覆盖几乎达到本轮O2的58.63292%；若换成当前时序的Top-K评分协议，即使给出全部已评分边的最佳匹配，也只有55.31974%的固定布局覆盖上界。这不表示移动后新发现UE可以免费提供给动作前actor；需要单独设计并验证可部署的关联时序。

**候选竞争仍局部且不均匀。** 每UAV候选数超过10的比例12.85%；在动作前后均有效的图中，仅1.63%的全体UE具有至少两个候选UAV。因此资源选择主要发生在少数局部超容量节点，UE在多个UAV间择优的空间较小。物理图与容量残余缺口为62.05人/步，约41.37个百分点；该值综合布局、感知、下行、回传和容量，不是单一无线因素的因果贡献。

极端示例为场景10019、第86步的一次随机评分：P0服务91人、P1与O1均为99人、O2为101人。它说明补位可以在某些布局恢复8人，但这是挑选的最大协议损失示例，不能代替均值。

建议下一轮优先检验**移动完成后再进行局部评分/关联**的时序对照，再决定是否增加补位；当前不改生产协议、不启动训练。若保持“动作前评分”的定义，需要接受已量化的等待缺口，且不能期待只优化Top-K排序就恢复O2。评分对数据率仍有价值，但本实验未证明扩散模型能优于简单SINR评分，也没有求完整奖励最优的关联上界。

“移动后评分”会改变当前一次性联合输出的定义，需要把运动和关联划为两个决策子步，明确增加的局部观测、推理与信令成本。不能免费把动作后信息加入动作前actor，更不能直接把O2集中式解当成已实现的分布式收益。
