# 一轮 Top-K 的容量浪费验证方案

**2026-11-03更新：** 当前工作基准已切换为容量10、覆盖＋0.1数据率的真实1M训练。新一轮使用该运行671,744步的best重新采集布局，详见[新基准诊断说明](topk_capacity10_coverage_throughput_diagnostic.md)。下文第1–9节保留最初容量20及其容量10反事实诊断的设计与结果，不能当作新模型结果。

本文件定义固定布局诊断及结果判读。独立实现已提供 `scripts/diagnose_topk_capacity.py`；生产环境关联代码保持原行为。场景采用 `configs/mappo_full_reward_baseline_1m.yaml`；被检查的协议来自 `ENVIRONMENT MODELING Diffusion_DPPO.md`。本轮只执行固定布局审计，闭环实验作为后续选项，不启动扩散训练。

## 1. 问题与最小例子

两架 UAV 容量均为1，两个 UE 均能连接两架 UAV。两架 UAV 都把 UE1排在第一位，一轮 Top-K 后 UE1选择一架，另一架空闲，UE2未服务。实际服务1人，但合法关联能服务2人。向被拒 UAV 的下一候选补位可以消除该例中的浪费。

另一个例子：一架 UAV 容量为1，时刻 t 的候选为 UE1、UE2，UE1排名更高；运动后 UE1失效、UE2仍有效。先 Top-K 再过滤会服务0人，若允许用已生成的 UE2评分补位，则可服务1人。

这两类损失分别来自重复提议和移动后失效，不等于无线模型没有可服务用户。

18架 UAV、每架容量20，共360个名额；只有150个 UE。因此即使覆盖100%，空闲率也至少为 1−150/360=58.33%。总空闲率和总容量利用率只作背景，不能单独作为容量浪费的证据。

## 2. 固定一次真实转移，定义可比较的候选图

保存动作前状态、各 UAV 的 F_i^t、全部原始评分、运动指令、UE运动随机状态及动作后物理状态。每个转移只运行一次运动与无线计算。后续所有关联求解共用完全相同的位置、SINR、回传可达性和容量。

定义三个边集：

- E_proposal：当前一轮 Top-K 提议经过 t+1物理门控后剩下的边。
- E_known：所有已生成评分且 t+1仍合法的边，即 {(i,m): m属于 F_i^t∩F_i^(t+1)}。它包括原来未进入 Top-K 的候选，完全遵守当前决策信息与时序。
- E_full：t+1全部合法边，即 {(i,m): m属于 F_i^(t+1)}。其中可能包括之前无法服务、没有评分的 UE；只用作事后诊断，不提供给 actor。

令 S_one 为原协议服务人数。因为每架 UAV 最多提出N条边，每个收到有效提议的 UE 都能选一架而不超容量，所以：

S_one = |至少收到一条有效提议的UE集合|。

在 E_proposal 上重新优化匹配不能进一步增加服务人数；要提高人数，必须引入未提议的候选边。评分仍可通过 UE 选择影响吞吐、故障保留或后续状态。

## 3. 每个转移运行四个影子求解

影子结果保存到诊断文件，但不写回环境的关联、历史或下一步观测，不消耗执行策略与 UE 的随机流。

| 求解 | 候选图与规则 | 用途 |
|---|---|---|
| P0：原协议 | t时刻 Top-K，t+1过滤，UE择优 | 得到 S_one |
| P1：保留已有连接的补位 | 从 P0出发，在 E_known 中，空闲 UAV 按原评分向未尝试的候选 UE 申请；已服务 UE 拒绝新申请，未服务 UE 接受最高分，有效服务不被撤销；重复到无新申请 | 得到 S_fill，衡量无需重新分配已有连接的补位收益 |
| O1：同信息最大覆盖 | E_known 上求容量约束的最大匹配 | 得到 S_known*，衡量所有已评分边可实现的最大服务人数 |
| O2：动作后物理最大覆盖 | E_full 上求相同最大匹配 | 得到 S_full*，区分“未评分的新增机会”和关联协议损失 |

P1每轮提议不得超过本机剩余容量，拒绝后不重复向同一 UE申请；平局按编号处理。消息计数包括向已服务UE发送后被拒绝的请求，不假设UAV免费获取全局未服务UE名单。由于不撤销 P0已有服务，它保证 S_fill≥S_one，但不保证达到最大覆盖。复杂案例需要通过重新分配已服务 UE、寻找增广路径才能增加人数。

O1/O2计算等价于整数最大流的容量约束二分匹配：源点→UAV容量N；合法 UAV→UE边容量1；UE→汇点容量1。实现采用确定性增广路径，目标只最大化服务人数，忽略评分，不新增大型求解器依赖。它们是集中式诊断上界，不是分布执行策略，不将全局解用作 actor 输入。

必须满足：

0 ≤ S_one ≤ S_fill ≤ S_known* ≤ S_full* ≤ M。

最大人数解可能不唯一，其吞吐或鲁棒性不是唯一值；不可把任意一个最大流解的完整奖励称为完整奖励的最优值。P0与P1的实际四项奖励可直接比较；O1/O2主要报告覆盖上界。

## 4. 可加和的覆盖缺口与辅助计数

每个转移计算：

- 原协议可避免缺口：L_protocol = S_known* − S_one。
- 简单补位可回收人数：L_fill = S_fill − S_one。
- 补位后剩余重分配缺口：L_reassign = S_known* − S_fill。
- 评分时序限制：L_timing = S_full* − S_known*。
- 当前物理图与容量的残余限制：L_feasibility = M − S_full*。

有精确分解：

M − S_one = L_protocol + L_timing + L_feasibility，
L_protocol = L_fill + L_reassign。

各量除以M可表示为覆盖率百分点。上述是固定转移、指定候选图下的分解，不代表长期训练损失的因果分解。

另外记录以下辅助计数，但不把它们相加当作服务损失，因为可能重复：

- 每机 |F_i^t|、|F_i^t∩F_i^(t+1)|、最终服务人数及剩余容量；
- 每 UE 在 E_known 中的候选 UAV 数，尤其是≥2的比例；
- 提议中的重复目标数、UE拒绝数、运动后失效提议数；
- 未服务 UE 中，有空闲 UAV 可以直接接纳的人数；
- 有未服务合法候选且仍有空位的 UAV 数；
- 补位轮数、额外消息数和求解耗时。

同一个空位可能对应多个候选 UE，不能把这些候选人数直接当作全部可恢复覆盖；最终以 P1和 O1结果为准。

## 5. 两层诊断与取样

### 5.1 小图正确性验收

覆盖重复提议、失效后补位、候选不足、无合法边、平局以及需要重分配的情况。

重分配例：容量均为1，UAV A可连接UE1/UE2，UAV B只能连接UE1；若 P0为 A→UE1，则保留已有连接的简单补位无法服务UE2，但最大匹配 A→UE2、B→UE1可服务2人。用这些图检查最大流、补位和缺口公式。

### 5.2 主场景固定转移审计

先使用32个固定诊断场景、完整400步轨迹，覆盖初期、展开、退化和边界阶段。可采用既有验证场景10000–10031，但必须称为诊断/验证场景，保留测试集不使用。

本轮从已有1M共享纯覆盖PPO运行的best采集物理转移；该best来自561,792步。它作为冻结运动教师，不称为完整奖励训练策略。原观察、一步历史和集中式关联继续用于生成真实轨迹。在同一转移上计算局部SINR教师评分、随机评分和常数评分，并运行 P0/P1/O1/O2。SINR评分为 sigmoid((SINR−门槛)/10)，不加入跳数或已有服务偏好。随机评分采用PCG64/SeedSequence([970001,场景,动作前时刻,重复编号])、每个固定转移重复20次；常数评分为0.5，按现有编号平局规则，仅作控制，不视为中立最优策略。所有候选评分采用float64排序。该批反映冻结教师访问布局上的机制损失。

后续可让“原运动教师＋局部评分教师＋一轮Top-K”真实闭环执行，按相同方法做影子审计。本轮不执行这一批。新关联会改变下一时刻的服务标记、动作和轨迹；因此未来需报告这一批自己的统计，不能认为第一批状态分布已经代表新协议。

未来获得扩散模型后，再对其自身轨迹复测同一审计。初期不需要新训练即可识别结构性问题。

评分干预保持物理状态不变，观察改变评分是否会改变关联、服务人数、吞吐和故障保留。O1/O2不依赖评分，应在同一候选图上保持不变。

若评分干预几乎不改变任务指标，应优先检查竞争与容量是否充分，不能凭评分头梯度非零推断该分支有效。

## 6. 输出及判读

逐转移保存场景ID、时刻、物理快照引用、候选边、原始评分、提议、各关联方案、四种人数与缺口、完整奖励贡献。连续轨迹保存为可重建数据；常规训练不逐步运行最大流。

图表与汇总：

1. 随时间的 S_one/M、S_fill/M、S_known*/M、S_full*/M曲线；全程、前100、最后100及终态汇总。
2. 未覆盖用户的 protocol/timing/feasibility 三部分分解；protocol进一步分为简单补位和重分配。
3. 非零协议损失的转移比例、每步缺口均值/中位数/P95、最大值；不要只展示极端案例。
4. 按候选人数、超容量程度、UE竞争程度分组统计缺口。
5. 固定场景10000/10001的候选边、提议、空位与未服务 UE图；极端案例另标为示例，不代替总体结果。
6. P0/P1实际吞吐、鲁棒性、覆盖与任务回报，以及补位额外消息和耗时。

先对每个场景内的时刻和随机评分重复求平均，再以场景为单位做2000次bootstrap（种子950001）。不把12800个相关时间步当作独立场景，也不把该区间称为训练种子置信区间。

判读：

- L_protocol显著、L_fill回收比例高：支持加入简单补位，再做闭环策略评估。
- L_protocol显著但 L_fill很小：需要处理重分配；不能仅追加一轮消息就宣称解决。
- L_protocol很小、L_timing显著：重点在先评分再移动的时序机会损失，不是容量补位。
- L_feasibility占主导：布局、感知、下行、回传及容量共同约束更强；本诊断不进一步宣称某一个无线因素是唯一原因。
- 协议覆盖损失很小但评分显著改变吞吐/鲁棒性：评分仍可能有完整任务价值，不能仅看覆盖否定它。

是否值得改协议还需结合覆盖增益、消息成本与完整任务回报；不能以一个小图反例或一个高空闲率直接宣布当前训练失败的根因。

## 7. 实现入口、保存与重建

从项目根目录执行完整32场景×400步审计：

```bash
OPENBLAS_NUM_THREADS=1 MKL_NUM_THREADS=8 OMP_NUM_THREADS=8 \
.venv/bin/python -u scripts/diagnose_topk_capacity.py
```

默认输出为 `analysis/topk_capacity_shared_best_diagnostic/`。包含逐场景 `trajectories/`、`audit/`，中文 `report.md`、`summary.json`、统计CSV、图表数据，以及PDF/SVG/PNG图。原始物理轨迹按场景压缩保存；各场景审计原子发布，失败时保留先前有效文件。

仅从已保存轨迹继续审计：

```bash
OPENBLAS_NUM_THREADS=1 MKL_NUM_THREADS=8 OMP_NUM_THREADS=8 \
.venv/bin/python -u scripts/diagnose_topk_capacity.py --phase audit --resume
```

该命令校验来源、配置和已保存场景哈希，跳过完整有效的审计块。若采集阶段中断，可用 `--resume` 从相同种子与原采样批次重新完成采集，随后重新审计；并不将已有文件当作可以任意拼接的新策略轨迹。

只重建报告和图表：

```bash
.venv/bin/python scripts/diagnose_topk_capacity.py --rebuild
```

重建不加载模型，不推进环境或消耗策略随机流。`provenance.json`记录源模型、源码、配置、实际best步数与种子；`execution.json`记录覆盖率复现、耗时、内存和哈希不变检查。源模型完整验证平均覆盖应为0.6816338541666667，容差为1e-6；不符合则停止后续审计。

## 8. 本轮执行结果（2026-11-02）

已完成32场景×400步、12,800条真实联合转移；每条转移额外检查教师评分、常数评分和20次随机评分。教师原轨迹平均覆盖为 **68.16338542%**，与历史验证完全复现。源模型文件与actor参数哈希保持不变。

| 评分 | 一轮Top-K覆盖 | 补位后覆盖 | 同信息最大覆盖 | 动作后物理最大覆盖 |
|---|---:|---:|---:|---:|
| SINR教师 | 64.774323% | 64.775781% | 64.778281% | 68.163385% |
| 常数 | 64.769740% | 64.777187% | 64.778281% | 68.163385% |
| 随机（20次均值） | 64.769224% | 64.775841% | 64.778281% | 68.163385% |

**容量浪费存在，但不是当前布局下的主要缺口。** 教师评分仅在74/12,800条转移（0.578125%）出现非零协议损失，最多损失2人。全程平均协议损失0.0059375人/步，相当于覆盖0.0039583个百分点。简单补位恢复0.0021875人/步，即0.0014583个百分点；配对场景95%区间为[0.00046875,0.00270833]个百分点。区间为正不等于具有较大的实际收益。随机评分补位收益也只有0.0066172个百分点。

**时序机会损失更明显。** 同信息最大覆盖64.778281%与动作后物理最大覆盖68.163385%相差 **3.385104个百分点**（5.077656人/步）。它来自合法边在移动后新增、此前没有评分的限制，不是重新运行同一候选图匹配即可恢复的容量损失。这里没有证明这些用户都能通过一个实际可部署的新协议立即获得服务，也没有验证长期闭环效果。

**评分可以改变归属，但在这些布局上改变覆盖和完整收益的空间较小。** 随机评分相对教师会在63.5945%的转移中改变至少一个UE的服务归属，但只有0.7980%的转移改变服务人数。随机评分平均覆盖较教师低0.005099个百分点；完整任务奖励的平均绝对变化为0.000157959，而教师P0每步平均完整奖励约0.969335。不能仅凭“63%的转移归属不同”判断该分支能获得强训练信号。

背景统计与这一现象一致：每UAV候选人数超过20的概率为 **0.173611%**；在同信息图中，具有至少两个候选UAV的UE占全体UE的 **1.480469%**。因此大多数名额选择和UE服务归属由物理可行性决定。该结论限于当前冻结教师访问的布局，不否定其他密度、无线设置或策略访问分布下的评分价值。

本轮不据此加入生产补位协议。后续更值得优先明确运动与关联的时序：是否接受当前已量化的约3.39个百分点等待缺口，或独立设计“移动后执行局部关联”的控制时序；同时确认研究所需的资源分配竞争在当前主场景是否足够丰富。改变时序或资源模型后必须独立对照，不能把O2全局事后上界直接提供给actor或当作已实现收益。

执行耗时约 **127.64秒**（采集72.94秒、审计41.50秒、报告12.54秒），进程峰值RSS约 **1.422 GiB**，输出约 **824.5 MiB**。相关25项测试通过，另完成短测和不重新采样的报告重建检查。固定场景拓扑和挑选的最大协议损失案例均已保存，后者明确标为示例。
